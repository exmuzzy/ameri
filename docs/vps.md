# VPS для ameri: выбор провайдера (сентябрь 2026)

Задача: отдельный VPS вне РФ для Streamlit + FastAPI + SQLite + LibreOffice + Caddy (`<ip>.sslip.io`, Let's Encrypt), вызовы `api.deepseek.com`.
Нужно: ~2 vCPU, 4 ГБ RAM, 40–80 ГБ NVMe, Ubuntu 24.04, публичный IPv4. Бюджет до ~2000 ₽/мес. Персональных данных клиентов нет, поэтому 152-ФЗ локализацию не требует.
Менеджеры открывают сайт из РФ, желательно без VPN.

Источники проверялись поиском 26.09.2026. Сайты многих хостеров (timeweb.cloud, vdsina.ru, hostkey, ps.kz, hoster.kz) напрямую открыть не удалось, цены взяты из выдачи и обзоров. Всё непроверенное помечено «проверить».

## 2. Доступность из РФ

- **TCP 16-20 («заморозка»)**. С июня 2025 ТСПУ обрывает HTTPS к подсетям крупных иностранных хостеров: после ~15–20 КБ в одном TCP-соединении пакеты перестают приходить. Сайт на Streamlit на таких IP фактически не работает. Затронуты по чекеру [hyperion-cs/dpi-checkers](https://github.com/hyperion-cs/dpi-checkers) (suite обновлён в сентябре 2026): Hetzner, OVH, DigitalOcean, Contabo, Vultr, Scaleway, Oracle, AWS, Google Cloud, Azure, Akamai/Linode, Cloudflare, Fastly, Gcore, CDN77, Melbicom, BuyVM. Подробнее: [net4people #490](https://github.com/net4people/bbs/issues/490), [Хабр](https://habr.com/ru/news/864700/), [РБК 07.04.2025](https://www.rbc.ru/technology_and_media/07/04/2025/67f3c50a9a7947ce5ec00ef7).
- **Российские провайдеры с зарубежными зонами** (Timeweb, VDSina, Hostkey) в эти списки не входят. Гарантий нет, поэтому после аренды обязателен тест из РФ (п. 4, шаг 7).
- **Сбои ТСПУ с 05.06.2026** задели и российских хостеров (Beget, Timeweb, Selectel, VDSina, FirstVDS и др.). Совет в обзорах — держать TLS 1.2 + HTTP/2 как запасной режим ([ebyebots](https://ebyebots.ru/blog/tspu-2026-pochemu-segodnya-sajty-i-hostingi-do-sih-por-ne-rabotayut-i-chto-delat/)). Caddy это умеет, если понадобится.
- **Белые списки на мобильном интернете.** В регионах с ограничениями через мобильную сеть открываются только IP из белого списка (Яндекс, VK и т. п.). **Любой** зарубежный VPS, как и обычный российский, там недоступен. Менеджерам нужен проводной интернет или Wi-Fi ([обзор](https://bothelp.io/ru/blog/belye-spiski-interneta-v-rossii)). Этот риск не устраняется выбором провайдера.
- **sslip.io.** Это только DNS: имя `1-2-3-4.sslip.io` резолвится в IP, а трафик идёт напрямую на наш сервер. NS сервиса: `ns-00.nip.io`, `ns-01.nip.io`, `ns-ovh.sslip.io` (OVH Варшава). DNS работает по UDP с маленькими ответами, поэтому TCP 16-20 его не касается. Упоминаний блокировки sslip.io/nip.io в реестре РКН не найдено, «проверить» на [2ip.io/rkn-blacklist](https://2ip.io/rkn-blacklist/). Риск есть: на этих доменах бывают фишинговые хосты ([список сервиса](https://gist.github.com/cunnie/39012802e86b965df63ffef1556480cf)), и домен могут заблокировать целиком.
- **api.deepseek.com.** Региональных ограничений для API нет, по состоянию на 2026 он доступен глобально ([обзор](https://theneuralbase.com/deepseek/qna/deepseek-api-availability-and-regions/)). В NL и DE запреты касаются госустройств и приложения, а не API. Из KZ ограничений не найдено. Проверить с сервера: `curl -sS https://api.deepseek.com/models -H "Authorization: Bearer $KEY"`.

## 3. Let's Encrypt и sslip.io / nip.io

| Факт | Источник |
|---|---|
| sslip.io и nip.io **не в Public Suffix List**, поэтому лимит LE общий на весь домен, а не на поддомен | [sslip.io #108](https://github.com/cunnie/sslip.io/issues/108), [PSL #335](https://github.com/publicsuffix/list/issues/335) |
| LE поднимал лимит для sslip.io до 50 000 сертификатов в неделю, но 09.02.2026 он был исчерпан: «too many certificates (50000) already issued for sslip.io» | [sslip.io #108](https://github.com/cunnie/sslip.io/issues/108) |
| nip.io: лимит поднят до 250 000 в неделю, запрос на 500 000 LE отклонил. При отказе совет: попробовать другой домен (nip.io ↔ sslip.io) или IP-сертификат | [nip.io](https://nip.io/) |
| Сертификаты LE на IP-адрес (профиль `shortlived`, 160 ч) общедоступны с 15.01.2026 | [LE 15.01.2026](https://letsencrypt.org/2026/01/15/6day-and-ip-general-availability) |
| Caddy: в 2.10 IP-сертификат LE отклонялся ([#7399](https://github.com/caddyserver/caddy/issues/7399)); в 2.11 есть профили ACME и IP-идентификаторы «проверить» | [releases](https://github.com/caddyserver/caddy/releases) |

Практически: сертификат выпускается один раз и продлевается раз в ~60 дней, попасть на окно исчерпания лимита маловероятно. Caddy повторяет попытки сам и при неудаче LE переходит на ZeroSSL (нужен `email` в глобальных опциях, «проверить»).

**Рекомендация:**
- **Основной:** `https://<a-b-c-d>.sslip.io`, Caddy + Let's Encrypt, в глобальных опциях указать `email`.
- **Запасной 1:** `<a-b-c-d>.nip.io`. Это другой зарегистрированный домен, у него свой лимит.
- **Запасной 2:** свой домен `.ru` или `.com` (~200–1000 ₽/год), A-запись на IP. Такой домен не зависит от общих лимитов и репутации sslip.io. Его стоит рекомендовать заказчику уже на старте.
- **Запасной 3:** IP-сертификат LE (Caddy ≥ 2.11, «проверить») или самоподписанный сертификат (решение Q24).

## 4. Рекомендация

**Основной: Timeweb Cloud, зона Франкфурт (DE), облачный сервер 2 vCPU / 4 ГБ RAM / 50–80 ГБ NVMe, Ubuntu 24.04, публичный IPv4.** Цену смотреть в [калькуляторе](https://timeweb.cloud/prices); если выходит больше 2000 ₽, брать 2/4/50 или ближайший фиксированный тариф. Почему этот вариант:
- оплата рублями картой РФ или СБП, закрывающие документы для юрлица, почасовая тарификация;
- снапшоты, бэкапы по расписанию и API в одной панели: удобно для `deploy/` и отката;
- IP-сети не из списков TCP 16-20; сервисы геолоцируют их как российские;
- Франкфурт, а не Амстердам: в Амстердаме в мае–июне 2026 было ~46 ч простоя. Альтернатива в том же аккаунте — Алматы (KZ).

**Запасной: VDSina, Амстердам, 2 vCPU / 4 ГБ / 100 ГБ NVMe за ~1200 ₽/мес** («проверить» для NL). Оплата: МИР, СБП, крипта. Второй запасной — Hostkey NL.
**Не брать:** Aeza (санкции OFAC), Hetzner, Contabo, DigitalOcean, OVH, Vultr (TCP 16-20 и/или оплата из РФ).

### Шаги для заказчика
1. Зарегистрироваться на [timeweb.cloud](https://timeweb.cloud) по e-mail и включить 2FA. Для юрлица заполнить реквизиты, чтобы получать закрывающие документы.
2. Пополнить баланс на 2–3 месяца картой РФ или по СБП (QR в разделе «Баланс и платежи»).
3. На своём компьютере создать SSH-ключ: `ssh-keygen -t ed25519 -C ameri`. Публичную часть (`~/.ssh/id_ed25519.pub`) добавить в панели: «SSH-ключи» → «Добавить».
4. «Облачные серверы» → «Создать»: регион **Франкфурт**, ОС **Ubuntu 24.04**, конфигурация 2 vCPU / 4 ГБ / 50–80 ГБ NVMe, публичный IPv4 включён, SSH-ключ выбран. Имя сервера — `ameri`.
5. Включить автобэкапы (ежедневно, хранить 7 копий). Перед каждым крупным обновлением делать снапшот.
6. Добавить в `~/.ssh/config`:
   ```
   Host ameri
       HostName <IPv4>
       User root
       IdentityFile ~/.ssh/id_ed25519
   ```
   Проверить командой `ssh ameri`. Передать исполнителю IP и алиас `ameri`.
7. **Приёмочный тест доступности, до развёртывания.** Из офиса и с домашнего интернета РФ, без VPN:
   - `ssh ameri`;
   - на сервере: `python3 -m http.server 8080`, потом с ПК в РФ: `curl -o /dev/null -w '%{size_download}\n' http://<IPv4>:8080/` на файле ≥ 1 МБ. Если скачивание зависает около 16 КБ — это TCP 16-20: пересоздать сервер в другой зоне (Алматы) или уйти к запасному провайдеру;
   - `dig +short <a-b-c-d>.sslip.io`;
   - с сервера: `curl -I https://api.deepseek.com`.
8. Открыть в панели или фаерволе порты 22, 80 и 443. Дальше работать по docs/plan.md, раздел 8, заменив `bishkek` на `ameri`.
