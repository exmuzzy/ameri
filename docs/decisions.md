# Протокол решений

Действующие решения по проекту ameri. Термины — в [CONTEXT.md](../CONTEXT.md), решения, которые трудно отменить, — в [docs/adr/](adr/). История обсуждения — в git.

## Принятые решения

| № | Вопрос | Решение |
|---|---|---|
| — | Интерфейс | Только сайт на Streamlit ([ADR-0003](adr/0003-streamlit-web-app.md)) |
| — | Основа | Прототип duct-calc («Расчётка воздуховодов»): Спецификация (.md/.xlsx/.docx/.doc/.csv) + Тип соединения → DeepSeek разбирает в JSON → проверки → расчёт кодом → XLSX по шаблону |
| Q1 | Инструмент разработчиков | [claude-ds](claude-ds.md): Claude Code, подключённый к DeepSeek (`deepseek-flash`) |
| Q2 | Руководитель и Администратор | Две роли с разными правами; один человек может совмещать обе |
| Q4 | Сервер | VPS Beget `ameri` (СПб, 2 CPU / 4 ГБ, 990 ₽/мес), https://159-194-254-146.sslip.io; установка `deploy/bootstrap.sh`, обновление кнопкой на сайте. Сервер `bishkek` — запасной вариант ([docs/handoff-bishkek.md](handoff-bishkek.md)) |
| Q8 | Утверждение изменений Харнеса | После подтверждения Руководителем в приложении — коммит сразу в `master`; откат через git |
| Q9 | Где хранится Харнес | Этот репозиторий, каталог `harness/` |
| Q10 | Стек | Python; выбор библиотек — за исполнителем |
| Q11 | Бюджет | До 2 000 ₽/мес на VPS, до $20/мес на DeepSeek на период настройки; приложение следит за расходом |
| Q12 | Инструменты Руководителя | ZCode или Cursor на компьютере Руководителя с копией репозитория |
| Q13 | Доступ инструментов к истории | Через API приложения |
| Q14, Q22 | Персональные данные клиентов | Не обрабатываются, маскирование не нужно; приложение предупреждает, если похоже, что они появились ([ADR-0002](adr/0002-no-client-pd.md)) |
| Q16 | Название | **ameri** |
| Q18 | Ограничения для категории организации | Компания не относится к ограниченным категориям |
| Q19 | Юридическое оформление ПДн | Не требуется, так как клиентских ПДн нет |
| Q20 | Подключение DeepSeek | Напрямую через `api.deepseek.com`, модель `deepseek-flash` (поддерживает изображения) |
| Q23 | Соседство с чужими сервисами | Актуально только для `bishkek`: ничего чужого не трогаем (см. handoff). На VPS Beget сайт один |
| Q24 | Домен и HTTPS | Автоматически: `<ip>.sslip.io` + Let's Encrypt; запасные варианты по порядку: `<ip>.nip.io`, свой домен, сертификат на IP или самоподписанный |
| Q26 | Аккаунт DeepSeek | Есть, ключ уже используется прототипом |

## Открытые вопросы

План исполняется со значениями по умолчанию, пока заказчик не ответит иначе.

| № | Вопрос | По умолчанию |
|---|---|---|
| Q27 | Как приложение пишет Харнес в GitHub | Deploy key с правом записи только в этот репозиторий |
| Q28 | Репозиторий публичный | Сделать приватным до переноса шаблона с ценами и Харнеса |
| Q29 | Перенос прототипа | Переносим `src/duct_calc`, тесты и шаблон; `DuctCalc.app` не нужен |
| Q30 | Единица работы | Проект; Направления — позже |
| Q31 | Типовые действия в MVP | Только Расчётка воздуховодов |
| Q32 | Вопросы Менеджеров к модели | Чат по Проекту — в v1 |
| Q33 | Вход | Логин и пароль, учётки заводит Администратор |
| Q34 | Где живут Правила | Простые — YAML в `harness/`, сложные — код через ZCode или Cursor |
| Q35 | Исправления | Исправление → Правило → проверка на Эталонах → подтверждение → коммит |
| Q36 | Наблюдение Руководителя | Страница «История» в приложении |
| Q37 | Нарезка метража | Если метраж делится на 1500 — по 1500, иначе на равные части не длиннее 1500 (как в КП: 2 мп → 2×1000) |
| Q38 | Зонт с одним размером | Размер — патрубок; купол = 2 × патрубок, если не указан. **Сделано** в прототипе 2026-09-27 (`with_umbrella_optional_neck_key`) |
| Q39 | Заголовки без количества («Вытяжка из химлаборатории») | Исправить в коде прототипа: считать заголовком раздела, как «Система В1». **Сделано** в прототипе 2026-09-27 (`is_section_heading`): строка без количества, типа и размеров в расчётку не идёт; с размерами, но без количества — красная |
| Q40 | «фланец20», «ф20» в спецификациях | Нет варианта по умолчанию — решает руководитель |
| Q41 | Соединения по торцам («раструб/труба») | Доработка прототипа после запуска сайта |
