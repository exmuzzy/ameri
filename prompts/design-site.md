# Промпт для агента: профессиональное оформление сайта ameri

> Передайте агенту всё, что ниже линии. Агент работает в этом репозитории (ветка `master`), у него должен быть Python и браузер (Playwright/Chromium) для скриншотов.

---

## Git — вливать в master

Заказчик явно разрешает и требует, чтобы вся работа оказалась в **`master`**: сайт обновляется только из неё. Если среда выдала рабочую ветку (`claude/...`), после каждого законченного шага вливай её в `master` (`git merge`), прогоняй `python -m pytest -q` и выполняй `git push origin master`. Pull request не создавай. Если push отклонён — остановись и сообщи заказчику ошибку.

## Роль

Ты — продуктовый дизайнер и фронтенд-разработчик с опытом внутренних B2B-инструментов (рабочие места сотрудников, CRM, панели операторов). Твоя задача — **красиво и профессионально оформить сайт ameri**, не ломая ни одной функции.

## Контекст

Прочитай перед работой: `AGENTS.md` (инварианты и карта кода), `README.md` (что есть на сайте), `CONTEXT.md` (термины), статьи в `docs/site/*.md`.

- **ameri** — рабочее место менеджеров компании, которая изготавливает химстойкие воздуховоды и вентиляторы из полипропилена (ПП). Пользователи — 2–10 менеджеров по продажам и их руководитель; работают весь день, за ноутбуками, иногда с телефона.
- Сайт сделан на **Streamlit** (≥ 1.45): `app/main.py` (навигация `st.navigation`, группы «Работа» и «Руководителю»), страницы в `app/views/`.
- Страницы:
  - вход;
  - **Чаты** — список слева, переписка справа, выбор действия над полем ввода, вложения, 👍/👎 и «✏️ Исправить и научить» под ответами ассистента;
  - **Новому сотруднику**, **О проекте**, **Как работать**, **Примеры работы** — статьи из Markdown;
  - **Качество** — метрики и таблица;
  - **Харнес** — вкладки;
  - **Настройки** — формы.
- Тон продукта: инженерный, спокойный, надёжный. Это инструмент для работы с расчётами и деньгами, а не лендинг. Ценности: ясность, скорость, аккуратность, доверие к цифрам.

## Что сделать

### 1. Визуальный язык
- **Палитра.** Нейтральная основа и один акцентный цвет. Предложи палитру, уместную для промышленной B2B-компании: сдержанный синий, графитовый или сине-зелёный; без кислотных оттенков. Нужны семантические цвета для статусов: готово — зелёный, требует уточнения — **красный** (это важный сигнал «позиция не распознана»), предупреждение — янтарный, информация — синий. Проверь контраст по WCAG AA.
- **Шрифт.** Один шрифт для интерфейса с хорошей кириллицей (Inter, IBM Plex Sans, PT Sans или похожий) и моноширинный для чисел и кода. Цифры в таблицах — табличные (`font-variant-numeric: tabular-nums`).
- **Шкалы.** Отступы кратны 4/8 px, радиусы, тени, размеры заголовков. Всё в CSS-переменных.
- **Иконки.** Сейчас используются эмодзи (💬 🎓 📐 📖 🧩 📊 🧠 ⚙️ 👍 👎 ✏️). Либо замени их на единый набор (Material Symbols — Streamlit поддерживает `:material/имя:` в `icon=`), либо обоснуй, почему оставить.
- **Логотип.** Простой текстовый логотип «ameri», читаемый в светлой и тёмной теме; `st.logo` в сайдбаре и favicon (`page_icon`).

### 2. Техническая реализация в Streamlit
- **Тема** — в `.streamlit/config.toml`, секции `[theme]`, `[theme.light]`, `[theme.dark]`, если версия поддерживает: `primaryColor`, `backgroundColor`, `secondaryBackgroundColor`, `textColor`, `font`, `baseRadius`, `borderColor` и т. д. Сначала используй штатные возможности темы, CSS — только там, где тема не дотягивается.
- **Свой CSS** — одним файлом `app/static/style.css` (или `app/style.css`), который подключает одна функция, например `app/views/theme.py: apply_theme()`, в начале `app/main.py`. Селекторы только по стабильным `data-testid` (`stSidebar`, `stChatMessage`, `stChatInput`, `stMetric`, `stDataFrame`, `stTabs`, `stButton` и т. п.). Никаких сгенерированных классов вида `st-emotion-cache-xxxx`: они меняются между версиями.
- **Шрифты** подключай через `@import` Google Fonts в CSS или через `[theme] font` и `[[theme.fontFaces]]`, если поддерживается. Добавь системный запасной шрифт.
- Не используй сторонние компоненты Streamlit без крайней необходимости. Если всё же нужно — добавь в `requirements.txt` с фиксированной версией и объясни, зачем.
- **Тёмная тема** должна выглядеть так же аккуратно, как светлая.

### 3. Экраны
- **Вход.** Аккуратная карточка по центру: логотип, одна строка о продукте, форма. Описание проекта под формой — короче и визуально вторично.
- **Чаты — главный экран, на него больше всего внимания:**
  - список чатов — компактные элементы с названием, автором и временем последнего сообщения; активный чат явно выделен;
  - сообщения менеджера, ассистента и руководителя («Исправление руководителя») различаются визуально;
  - вложения — аккуратные «чипы» файлов;
  - предупреждения и сводка расчётки читаются легко;
  - выбор действия над полем ввода — как сегментированный переключатель (`st.segmented_control` или `st.pills`, если есть в версии), тип соединения — рядом;
  - кнопки оценки и «Исправить и научить» — вторичные, не спорят с текстом ответа;
  - длинная переписка удобно прокручивается, поле ввода всегда доступно.
- **Статьи.** Удобная ширина текста (60–80 знаков), типографика заголовков, таблиц, списков и блоков кода; оглавление для длинной статьи «Примеры работы».
- **Качество.** Метрики — карточки одинаковой высоты; таблица с выравниванием чисел по правому краю; блок «Последние плохие ответы» — список карточек.
- **Харнес.** Карточки предложений на утверждение с понятными кнопками «Утвердить» (основная) и «Отклонить» (вторичная); история изменений — читаемый список, а не сырой лог.
- **Новому сотруднику.** Прогресс-бар и чек-лист как пошаговый онбординг, заметная кнопка «Открыть учебный чат».
- **Пустые состояния** (нет чатов, нет данных, нет предложений) — дружелюбный текст и подсказка следующего шага.
- **Мобильная ширина (375 px).** Ничего не вылезает по горизонтали, колонки складываются, кнопки нажимаются пальцем.

### 4. Тексты интерфейса
Проверь подписи кнопок, заголовки и подсказки: коротко, по-русски, единообразно, без технического жаргона для менеджеров. Меняй тексты только ради ясности. Не меняй термины из `CONTEXT.md` («Чат», «Расчётка», «Харнес», «Исправление», «Эталон»…).

## Ограничения — обязательно

1. **Функциональность не меняется.** Не трогай логику в `src/ameri/`, права, работу с базой, харнесом и DeepSeek. Правки в `app/views/*.py` — только разметка и оформление: порядок и группировка виджетов, `st.container(border=True)`, колонки, иконки, подписи. Все ключи виджетов (`key=`) и поведение кнопок сохраняются.
2. **Тесты зелёные:** `python -m pytest -q` перед каждым коммитом.
3. **Никаких внешних трекеров, аналитики и CDN-скриптов.** Разрешены только шрифты Google Fonts.
4. **Репозиторий публичный:** не добавляй реальные данные клиентов, цены, секреты.
5. Изменения — небольшими коммитами в `master` с понятными сообщениями на английском.

## Как проверять

1. Запусти сайт локально: `README.md` → «Локальная разработка». Нужен `var/users.toml` с менеджером и руководителем. Для наполнения создай 2–3 чата с сообщениями через `ameri.store.Store`: без ключа DeepSeek ассистент ответит «ключ не задан», этого достаточно для вёрстки.
2. Playwright: скриншоты **до и после** каждого экрана из раздела 3 — светлая и тёмная тема, ширина 1440 и 375 px, под менеджером и под руководителем. Сохрани их в `docs/design/before/` и `docs/design/after/`.
3. Проверь контраст ключевых пар цветов (текст/фон, акцент/фон, красный статус/фон) и запиши результаты.
