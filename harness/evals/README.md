# Эталоны

Эталон — реальная спецификация и то, как должна разбираться каждая её позиция. Все изменения харнеса проверяются на эталонах: правило, которое ломает эталон, не утверждается.

Каждый каталог содержит:
- `spec.*` — файл запроса клиента (метаданные очищены, персональных данных нет);
- `expected.yaml` — ожидаемый разбор: для каждой позиции подстрока её текста (`line`), ожидаемый тип изделия (`type`, необязательно) и может ли позиция уйти на уточнение (`red`).

Запуск (нужны ключ DeepSeek и прототип duct-calc):

```bash
DEEPSEEK_API_KEY=... AMERI_DUCT_CALC_DIR=/путь/к/duct-calc python tools/run_evals.py
python tools/run_evals.py --no-harness   # тот же прогон без правил харнеса — для сравнения
```

Эталонные ответы для `himlab` взяты из коммерческого предложения компании на этот запрос. Само КП в репозиторий не кладётся: в нём контакты клиента и цены.

`b2b-rudnik-pp` и `b2b-pnd-analog` — кандидаты из открытых перечней позиций закупок (B2B-Center): строки позиций выгружены в XLSX дословно, без организатора и адреса, ссылка — в поле `source`. Ожидания для них составлены по исследованию отрасли (docs/industry-research.md) и ждут проверки руководителем; у `b2b-pnd-analog` есть столбец «Площадь по деталировкам» — по нему можно сверять площади расчётки.
